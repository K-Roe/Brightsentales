# Application architecture

## P4 saved episode playback (2026-10-25)

`Episode.sceneIds` and `productionBlocks` remain the ordered source of truth. Repeated scene IDs become separate occurrences with their own `index` and `start`; no episode schema or storage migration is introduced. `EpisodeMaker.tsx` retains its browser playback, audio, WebM and save/reopen flow and adds a compact `EpisodeUnityPreview` for saved episodes. Browser playback and Unity preview both use cuts at scene boundaries. Intros and credits remain available in the browser and are explicitly rejected by the current Unity episode preview.

`studioEpisodeBridge.ts` maps each occurrence through the existing `studioSceneConfig` and hashes one versioned episode payload. `episodePlaybackClips` maps scene clips to episode time and leaves episode music on the global clock; clips are bounded to the episode end in the transfer payload without changing saved clips. `transferStudioAudioClips` reuses P3's same-origin relay and deduplicates media IDs. The bridge accepts `episode.load/play/pause/stop/status/reset` with revision validation and a bounded request body.

The experimental Unity `StudioScenePlayer` now evaluates each occurrence's existing character/camera renderer at local time while its episode clock advances globally. It clears actors absent from the next scene at a cut, reuses P3 media download/hash/decode and AudioSources, and keeps episode music alive across cuts. Scene music is ducked while episode music is active, matching browser playback. Existing `studio.*` single-scene commands and the frozen Cartoon Engine V1.1 path remain separate. See [P4 proof](../proofs/cartoon-foundation-p4/REPORT.md).

## Isolated P3 scene audio transfer (2026-10-25)

`AudioAsset.blob` remains in the existing IndexedDB Audio Library; `TimedScene.audio` and Studio Backup schemas are unchanged. For Unity preview, `studioAudioTransfer.ts` hashes only assets referenced by the saved scene and POSTs their raw bytes to `/api/studio-audio` on the current local Studio origin. The existing `scripts/studio.cjs` launcher owns a bounded, in-memory relay with same-origin upload, ID/MIME/size/SHA-256 checks and unguessable retrieval URLs. Bytes never enter the 32 KB Unity `/command` JSON. No media persists in the relay across launcher restarts.

`studioSceneBridge.ts` adds audio asset references and clip timing to version 3 scene config, included in the existing revision hash. Audio-free scenes continue using version 2. A clip extending beyond the scene end is truncated in the preview payload only, preserving stored data. The isolated Unity Phase 2 `StudioScenePlayer` validates the references, downloads/rehashes/decodes before Play, and uses its scene clock for start, trim, volume and fades. `studio.status` reports loading and media failure; Reset disposes clip sources. `StudioSceneUnityPanel.tsx` coordinates transfer, loading status and playback through the existing bridge. Full episode playback and cross-scene music continuity remain outside the single-scene player; see [P3 proof](../proofs/cartoon-foundation-p3/REPORT.md).

## Studio 3.1 Bright Speak message amendment (2026-10-25)

Communicate Message was already represented by `PhoneAction.message` inside the existing `TimedScene.phone` array. The professional `SceneTimeline.tsx` now renders selectable phone clips, and `SceneMaker.tsx` edits the selected clip's text in its contextual Inspector. `phoneStateAt` and the shared `scenePreview.ts`/`phoneArt.ts` Canvas path still own timed playback and rendering. Missing `message` on an older saved action resolves to the original starter phrase in `phone.ts`; storage and Backup schemas remain unchanged. Text-only actions carry no speech clip ID. Optional saved speech remains on the existing audio path. [Amendment proof](../proofs/studio-3.1/bright-speak-amendment/REPORT.md).

## Studio 3.1 direct animation layer (2026-10-25)

Studio 3.0 is now part of main. Studio 3.1 changes the default Studio tab from Projects to Scenes; `App.tsx` remains the shared owner of saved libraries, workspace switching and persistence. `SceneMaker.tsx` resumes the most recent saved `TimedScene` or opens a Living Room draft and retains Classic's existing path. `Studio31Menu.tsx` provides working editor commands; `studio31.css` scopes the compact desktop layout to the professional editor using existing appearance tokens. The same stage Canvas, `scenePreview.ts` renderer, `timedScenes.ts` model, `SceneTimeline.tsx` and `timelineEditing.ts` handle character placement, Walk destination, actions, playback and timing. No scene schema, backup format, alternate animation engine, approved artwork or Unity bridge service was added. A saved scene still enters the existing `StudioSceneUnityPanel.tsx` and `studioSceneBridge.ts` path for optional Unity preview. See [Studio 3.1 proof](../proofs/studio-3.1/REPORT.md).

## Studio 3.0 experimental presentation layer (2026-10-24)

`App.tsx` remains the single state owner for characters, places, timed scenes, episodes, audio, projects, backups and restore. `workspacePreference.ts` stores only the selected interface (`studio3` by default or `classic`) in a separate browser key, outside Studio Backup v8 and project schemas. Both layouts render the same tool components and use the same save and validation handlers. `Studio3Shell.tsx` supplies navigation, a project overview from the existing libraries, and Workspace Settings. `studio3.css` extends the existing appearance tokens and is scoped to the new shell.

The Cartoon Editor reflows the existing `SceneMaker.tsx` stage, action inspector, camera panel, timeline and audio panel. It keeps the same scene state and Canvas renderer. Switching layouts retains the editor state; leaving an unsaved editor prompts first. Unity preview remains in `StudioSceneUnityPanel.tsx` and the Phase 2 bridge; the shell reports its optional connection status. No embedded Unity Game view or new renderer was added. See [Studio 3.0 proof](../proofs/studio-3/REPORT.md).

**Experimental saved-scene seam (2026-10-24):** `StudioSceneUnityPanel.tsx` reads saved `TimedScene` objects supplied by `App.tsx`. `studioSceneBridge.ts` validates and converts the supported subset into a versioned payload, hashes it as a content revision, then posts `studio.*` commands to the existing loopback `/command` bridge. **Unity integration audit (2026-10-24):** The older `unityBridge.ts`/`BrightTalesBridgeV0.cs` scene contract selects a fixed 26-second Living Room timeline; the isolated Phase 1 path now transfers the supported subset of a saved `TimedScene`. Saved `Episode` objects are not transferred. `sceneVideoExport.ts` and `EpisodeMaker.tsx` already contain browser WebM episode export. ## Unity Bridge V1 experimental Max import

The separate Unity 6.6 project keeps the approved Max original PNG as an isolated byte-identical sprite asset. A second transparent sprite is derived from the existing `eyeLayers.ts` Brightling Life V2 eyelid renderer, registered over the unchanged full-body image. `MaxBridgeCharacter` enables that eyelid sprite for the approved 0.15-second closed interval. The existing V0 localhost HTTP receiver routes `POST /command` with `max.blink` to Unity's main-thread `Update()` and acknowledges command acceptance. ## Living World V1.1 experimental polish

## Living World V1 opt-in behaviour layer

`livingWorld.ts` derives a per-character activity plan from saved scene data, stable IDs and absolute scene time. Its bounded Living Room floor corridor, points of interest and character-separation checks choose quiet pauses or approved side-walk cycles during gaps in scripted control. It returns to the script's position before the next action and never changes `stateAt` action timing. `scenePreview.ts` and camera follow read the same world state; Scene Maker and Episode Maker use that renderer for preview/export. `livingWorld: { enabled: true }` is optional in timed-library v1, with validated optional per-character probability preferences. Scene Maker keeps an ON/OFF control. Brightling Life V2 remains the continuous visual layer. See the [30-second V1 proof](../proofs/living-world-v1/REPORT.md); Karl visually approved V1 on 23 October 2026.

## Brightling Life V2 experimental controller

`brightlingLife.ts` provides character-ID-seeded blink and breath channels evaluated from absolute scene time. `eyeLayers.ts` creates transparent, tightly cropped eyelid layers registered to the current template pose; custom Brightlings use the same geometry on their recoloured sprites. `scenePreview.ts` composes those layers over the approved full-body frame and adds small body motion without changing action timing or scheduling new timeline actions. `life.mode: 'v2'` opts a scene into this path; absent `life` and existing V1 settings retain their earlier behaviour. Scene Maker keeps both V1 and V2 controls, and Scene Maker/Episode Maker previews and exports use the same renderer. Unsupported provisional gesture eyes remain unchanged pending reviewed registration. See the [V2 proof](../proofs/brightling-life-v2/REPORT.md); Karl approved V2 behaviour on 23 October 2026.

## Cartoon Life V1 experimental layer

Timed scenes may carry optional `life: { enabled: true, ambience?: boolean }` while keeping library version 1 and legacy scenes unchanged. `cartoonLife.ts` evaluates deterministic idle/anticipation/walk/settle transforms from absolute scene time and makes temporary blink Canvases from the original Max/Maxine standing sprites; source PNGs are not changed. `scenePreview.ts` applies these restrained foot-anchored transforms and clipped Living Room window ambience in the existing shared Canvas renderer. Scene Maker has one opt-in checkbox. Scene and episode previews and exports reuse that renderer and Camera V1. The current whole-body frames cannot provide independent head turns or eye gaze, and the flattened background cannot move curtains independently. See the [experimental proof](../proofs/cartoon-life-v1/REPORT.md); Karl's visual/listening approval is pending.

## Camera System V1

Timed scenes may carry optional `camera` keyframes. `camera.ts` evaluates Wide, Medium and Close-Up views from absolute scene time, using the existing `stateAt` character positions for focus and follow. Its smoothstep interpolation and viewport clamp feed a Canvas transform in `drawScenePreview`; characters, props, place art and Bright Speak remain in the same scene coordinate system. Scene Maker preview, scene WebM and Episode Maker preview/export all call that renderer. The camera lane is part of `SceneTimeline`, and Scene Maker edits the same saved keyframes. Scenes without `camera` keep the original wide view; the timed library stays at version 1, so existing Studio Backup validation and restore retain the optional field without a second storage path.

This is a local React/TypeScript/Vite application. `scripts/studio.cjs` launches it: it serves the app (Vite in development, the built `dist/` in production) and manages the loopback Python voice service used by Voice Maker for installed Piper/Kokoro models and FFmpeg processing, so users never start Python themselves. There is no cloud requirement. `src/main.tsx` mounts `src/App.tsx`, which owns Studio navigation, shared saved libraries, Playground state and Studio Backup commands. Most editor state lives in the relevant React component until Save.

## Artwork and rendering

- Approved original Max/Maxine PNGs, alternative built-in outfit PNGs and Living Room artwork live under `public/art/`. Do not modify them without a separate approved artwork milestone.
- Custom Brightlings keep stable IDs, names, template and three colours. `maker.ts` recolours the template's original nine PNG poses using masks under `public/recolour-masks/`; it does not redraw the body or generate runtime AI art.
- Timed previews use a 1672×941 Canvas. `scenePreview.ts` draws the place background, evaluates each character at the requested time, sorts visible characters by foot Y for depth, and selects original/custom outfit sprite packs. Side frames mirror for leftward travel. The scene clock determines walk and wave poses, so seeking does not need previous frames.
- The Playground has its own existing movement/render loop in `App.tsx`. Preserve its established behaviour when extending the timed editor.

Studio Backup format **8** contains character definitions, legacy Playground scene, Places organisation, timed scenes, episodes, intros, credits, editable music projects and audio files as base64 plus SHA-256. It does not duplicate built-in artwork. Older backup versions are validated and normalised; older scenes and characters retain their IDs. Restoring a version 5 or older backup carries no intros, a version 6 or older backup carries no credits, and a version 7 or older backup carries no music projects, so existing local intros, credits and music projects are preserved rather than cleared. Character-only **Export Library** is not a complete Studio backup. Browser site-data clearing still removes live local data, so a downloaded Studio Backup is the separate recovery copy.

F4 coordinates restores across IndexedDB and localStorage: one IndexedDB transaction snapshots old audio and installs new audio; a pending/committed localStorage marker determines whether startup rolls both stores back or keeps the new state. Recovery runs before React mounts. The snapshot temporarily needs extra browser storage. On persistent storage failure the app blocks editing rather than loading mismatched data. A downloaded backup remains essential against browser site-data loss.

Voice Maker retains Backup v8 and adds an optional validated `voiceSettings` field. Its localStorage settings are part of the same restore journal as the saved projects; older backups without the field retain current voice settings. Original and edited recordings are separate existing `AudioAsset` records. Scene-only WebM export is bounded to two minutes and does not implement M6.7 episode assembly or M6.8 full-production export.

## Timing and future extension seams

- Timed scenes store action seconds relative to the scene; an episode stores scene references and uses a global clock. `episodePosition` converts global time to scene-local time. `episodePlaybackClips` offsets scene audio at each occurrence, including repeated scene IDs, while episode music retains its global clock.
- Speech in M6.4 adds attributed audio clips through the existing asset/clock/backup path and keeps non-verbal Brightlings valid. M6.5 introduces intros as a timed scene plus titles and M6.6 introduces credits as ordered lines presented through `creditsAsScene`; neither adds a second scene format or renderer. M6.7 assembly should compose intro, scenes and credits by stable reference on one global production clock, preserving all three existing formats.
- Complete production export in M6.8 must validate a playable file with picture and sound. Voice Maker V1 provides a verified scene-only WebM through the existing scene renderer and saved audio assets; it does not assemble episodes. M6.6A music projects should reuse rendered Audio Library WAV assets until the one-step PCM re-render variation is resolved.
